# Proposal: Add Note Subcategory Filter

## Overview

为笔记列表添加子分类过滤功能，允许用户通过点击标签来过滤特定子分类的笔记。

## Context

当前系统中，笔记按照 `src/note/` 下的第一层目录分为大分类（如 game, program, study_note 等）。在某些大分类下，存在第二层子目录作为更细粒度的分类（如 program/css, program/javascript, study_note/LLM 等）。

目前的 NoteList 组件只能显示当前大分类下的所有笔记，缺乏对子分类的过滤能力。这在笔记数量较多时，用户难以快速定位到特定子分类的内容。

## Problem Statement

**用户需求**：

1. 查看当前大分类下所有的子分类
2. 默认显示该大分类下的所有笔记
3. 点击某个子分类标签后，只显示该子分类的笔记
4. 能够清除过滤，重新显示所有笔记

**技术需求**：

1. 从笔记目录结构中提取子分类信息
2. 使用 Ant Design Tag 组件展示子分类
3. 在 NoteList 组件上方添加子分类过滤栏
4. 实现子分类过滤逻辑，与现有的搜索和排序功能兼容

## Proposed Solution

### 功能设计

1. **子分类提取**
   - 从 `note-directory-structure.json` 中提取二级目录作为子分类
   - 对于没有子分类的大分类（如 history, novel），不显示过滤栏

2. **UI 设计**
   - 在 NoteList 上方添加一行 Tag 组件
   - 包含"全部"标签 + 各子分类标签
   - 选中状态通过 Tag 的 checkable 属性实现
   - 响应式布局，支持多行显示

3. **交互设计**
   - 默认选中"全部"，显示所有笔记
   - 点击子分类标签，仅显示该子分类的笔记
   - 再次点击已选中的标签，回到"全部"状态
   - 切换大分类时，重置为"全部"状态

4. **过滤逻辑**
   - 在现有的搜索和排序逻辑基础上，增加子分类过滤
   - 过滤优先级：全局搜索 -> 子分类过滤 -> 排序 -> 分页

### 技术实现

1. **数据结构**
   - 使用 `note-directory-structure.json` 获取目录结构
   - 提取子分类名称列表

2. **组件修改**
   - 在 NoteList 组件中添加子分类过滤状态
   - 添加 CategoryFilter 子组件或内联实现标签栏
   - 更新过滤逻辑

3. **样式设计**
   - 使用 SCSS 模块化样式
   - 响应式断点适配
   - 与现有设计风格保持一致

## Impact

### Benefits

1. **用户体验提升**
   - 快速定位特定子分类的笔记
   - 减少滚动和搜索时间
   - 提供更清晰的内容组织视图

2. **可维护性**
   - 利用现有的目录结构，无需额外的元数据
   - 与自动路由生成机制兼容
   - 扩展性好，支持动态增加子分类

### Risks

1. **性能考虑**
   - 子分类数量过多时，标签栏可能过长
   - 建议限制显示数量或使用下拉菜单（可选优化）

2. **兼容性**
   - 需要确保与全局搜索、排序、分页功能的协同工作
   - 需要测试边界情况（无子分类、单个子分类等）

## Alternatives Considered

1. **使用下拉菜单而非标签**
   - 优点：节省空间
   - 缺点：需要额外点击，不够直观
   - 决策：先使用标签，后续可优化

2. **使用侧边栏过滤**
   - 优点：不影响列表区域
   - 缺点：需要较大的布局调整
   - 决策：保持简单，使用顶部标签栏

## Open Questions

1. ❓ 子分类标签的排序方式？
   - 选项：字母序、笔记数量、自定义顺序
   - 建议：默认字母序，可后续优化

2. ❓ 是否需要显示每个子分类的笔记数量？
   - 建议：可在 Tag 上显示数量徽章（可选功能）

3. ❓ 多级子分类（3级及以上）如何处理？
   - 当前方案仅处理2级
   - 建议：暂不支持，未来可扩展
