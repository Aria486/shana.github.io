# Proposal: 添加天气动态背景

**变更 ID**: `add-weather-background`  
**类型**: 新功能  
**优先级**: P2 (增强体验)  
**预估工作量**: 2-3 天  
**提议人**: User  
**创建日期**: 2026-01-21

---

## 动机 (Motivation)

当前博客页面背景单调，用户体验缺乏趣味性和视觉吸引力。通过添加基于真实天气数据的动态海滩背景动画，可以：

1. **提升视觉体验**: 动态动画增加页面活力和美观度
2. **增强互动性**: 天气数据与现实世界联动，提供个性化体验
3. **展示技术能力**: Canvas/SVG 动画 + 第三方 API 集成
4. **品牌形象**: 海滩主题契合博客的轻松、随性氛围（"想到啥写啥"）

### 用户价值

- 访问博客时看到与当地天气同步的海滩场景（晴天、下雨、多云等）
- 流畅的动画效果（波浪、云朵、雨滴等）增加停留时间
- 不同天气状态提供新鲜感，鼓励重复访问

---

## 约束与假设 (Constraints & Assumptions)

### 技术约束

1. **性能要求**:
   - 动画不能影响页面主要功能（笔记加载、搜索等）
   - 移动端性能优化（低端设备可降级或禁用动画）
   - 首屏加载时间增加 < 500ms

2. **浏览器兼容性**:
   - 支持现代浏览器（Chrome 90+, Firefox 88+, Safari 14+, Edge 90+）
   - 使用 Canvas 2D API（广泛支持）或 SVG 动画
   - 优雅降级：不支持的浏览器显示静态背景

3. **现有技术栈**:
   - React 19.1.1 + TypeScript
   - 已有 `Season/Summer.tsx` 组件作为动画参考（波浪效果）
   - SCSS 模块化样式
   - 主题切换支持（明暗模式）

### 业务约束

1. **天气 API**:
   - 使用免费天气 API（OpenWeatherMap/WeatherAPI.com 免费额度）
   - 日请求限制（通常 1000-10000 次/天）
   - 需处理 API 失败情况（网络错误、超限等）

2. **隐私与合规**:
   - 需用户同意获取地理位置（浏览器 Geolocation API）
   - 提供手动输入城市选项（无需位置权限）
   - 缓存天气数据（减少 API 调用，localStorage）

3. **用户控制**:
   - 提供开关控制背景动画（用户设置）
   - 响应系统"减少动画"偏好（`prefers-reduced-motion`）

### 假设

1. 用户主要在桌面端浏览（优先优化桌面体验）
2. 大部分用户允许地理位置访问或愿意手动输入城市
3. 天气数据每小时更新一次足够（缓存 1 小时）
4. 海滩场景适合所有笔记类别（编程、历史、游戏等）

## 提议的解决方案 (Proposed Solution)

### 高层设计

创建一个 `WeatherBackground` 组件，集成到 `BlogLayout` 或 `AppLayout` 中，根据天气数据渲染动态海滩场景。

#### 架构组件

```
WeatherBackground (容器组件)
├── WeatherService (天气数据服务)
│   ├── 获取用户位置 (Geolocation API)
│   ├── 调用天气 API (OpenWeatherMap)
│   └── 缓存管理 (localStorage)
├── BeachScene (Canvas 场景渲染)
│   ├── Sky (天空层 - 根据天气变色)
│   ├── Clouds (云层 - 多云/阴天)
│   ├── Rain (雨层 - 下雨)
│   ├── Sun (太阳 - 晴天)
│   ├── Ocean (海洋层 - 波浪动画)
│   └── Beach (沙滩层 - 静态/简单纹理)
└── WeatherSettings (用户设置面板)
    ├── 开关动画
    ├── 手动输入城市
    └── 刷新天气数据
```

### 天气状态映射

| 天气状态 | API 代码 (OpenWeatherMap) | 场景效果                       |
| -------- | ------------------------- | ------------------------------ |
| 晴天     | `Clear` (800)             | 蓝天 + 太阳 + 平静海浪         |
| 多云     | `Clouds` (801-804)        | 灰蓝天空 + 云朵漂浮 + 海浪     |
| 雨天     | `Rain` (500-531)          | 深灰天空 + 雨滴下落 + 激烈海浪 |
| 雷暴     | `Thunderstorm` (200-232)  | 暗灰天空 + 闪电 + 雨滴 + 大浪  |
| 雪天     | `Snow` (600-622)          | 白灰天空 + 雪花飘落 + 平静海面 |
| 雾/霾    | `Mist/Fog` (701-781)      | 朦胧天空 + 模糊海平线          |

### 动画技术方案

**选择 Canvas 2D API**（而非 SVG）理由：

- 性能更好（粒子系统如雨滴、雪花）
- 更易实现复杂动画（波浪流体模拟）
- 参考现有 `Summer.tsx` 波浪效果迁移到 Canvas

#### 关键动画实现

1. **波浪动画**:
   - 正弦波函数 + 帧动画
   - 参数：振幅、频率、相位（根据天气调整）

2. **云朵动画**:
   - 多层云（远近景）以不同速度水平移动
   - 使用 `requestAnimationFrame` 循环

3. **雨滴动画**:
   - 粒子系统（200-500 粒子）
   - 垂直下落 + 轻微角度（风向）
   - 落到海面产生涟漪

4. **太阳/月亮**:
   - 静态或缓慢旋转光晕
   - 根据时间段显示（日出/日落渐变）

### 天气数据流

```
用户访问博客
    ↓
检查 localStorage 缓存（是否有最近 1 小时的天气数据）
    ↓ (无缓存或过期)
获取用户位置（Geolocation API）
    ↓
调用天气 API (OpenWeatherMap)
    ↓
解析天气数据 (温度、状态码、描述)
    ↓
存入 localStorage (带时间戳)
    ↓
更新 WeatherBackground 组件状态
    ↓
渲染对应天气场景
```

### 用户设置

新增全局设置（存储在 `GlobalDataProvider`）：

```typescript
interface WeatherSettings {
  enabled: boolean; // 是否启用背景动画
  location: {
    type: "auto" | "manual"; // 自动定位或手动输入
    city?: string; // 手动输入的城市名
    coords?: { lat: number; lon: number }; // 自动定位坐标
  };
  animationQuality: "high" | "medium" | "low"; // 动画质量
  updateInterval: number; // 天气更新间隔（毫秒）
}
```

## 技术决策 (Technical Decisions)

### 决策 1: Canvas vs SVG

**选择**: Canvas 2D API

**理由**:

- ✅ 性能优势：粒子系统（雨/雪）渲染更高效
- ✅ 复杂动画：波浪流体模拟更流畅
- ✅ 团队熟悉度：现有 `Summer.tsx` 使用 CSS 动画，Canvas 学习曲线适中
- ❌ SVG 优势（可缩放、DOM 操作）对本场景不重要

### 决策 2: OpenWeatherMap vs WeatherAPI.com

**选择**: OpenWeatherMap

**理由**:

- ✅ 免费额度更高（60 次/分钟，100 万次/月）
- ✅ 文档完善，社区活跃
- ✅ 数据可靠性高（全球覆盖）
- ❌ WeatherAPI.com 免费额度较低（100 万次/月，但单次调用返回数据更丰富）

### 决策 3: 实时动画 vs 预渲染视频

**选择**: 实时 Canvas 动画

**理由**:

- ✅ 交互性：可根据天气动态切换
- ✅ 包体积小：无需大视频文件
- ✅ 灵活性：可调整动画参数（速度、密度等）
- ❌ 预渲染视频性能更好，但缺乏灵活性且文件大

### 决策 4: 组件集成位置

**选择**: 集成到 `BlogLayout` 作为固定背景层

**理由**:

- ✅ 全局生效：所有页面共享背景
- ✅ 性能优化：背景组件只渲染一次，不随路由变化重新挂载
- ✅ 层级清晰：背景层 (z-index: -1) 不影响前景内容
- ❌ 备选方案（AppLayout 集成）会导致每次路由切换重新渲染

## 风险与缓解 (Risks & Mitigation)

### 风险 1: 性能影响 (High)

**描述**: Canvas 动画可能导致低端设备卡顿，影响用户体验。

**缓解策略**:

1. 实现分级动画质量（高/中/低）
2. 检测设备性能（CPU/GPU 能力）自动降级
3. 移动端默认低质量（减少粒子数、降低帧率）
4. 提供完全禁用选项（用户设置）
5. 监控 FPS，低于 30fps 自动降级

### 风险 2: API 配额超限 (Medium)

**描述**: 免费 API 额度耗尽导致功能失效。

**缓解策略**:

1. 缓存机制（1 小时有效期，减少请求）
2. 请求限流（同一用户每小时最多 1 次请求）
3. 优雅降级：API 失败时显示默认晴天场景
4. 监控 API 使用量，接近限额时发出警告
5. 备用 API（WeatherAPI.com 作为 fallback）

### 风险 3: 用户隐私担忧 (Medium)

**描述**: 用户可能不愿意分享地理位置信息。

**缓解策略**:

1. 明确的权限请求提示（说明用途）
2. 提供手动输入城市选项（无需位置权限）
3. 默认使用 IP 定位（粗略位置，无需浏览器权限）
4. 隐私政策说明（不存储/分享位置数据）
5. 可随时撤销位置权限（浏览器设置）

### 风险 4: 浏览器兼容性 (Low)

**描述**: 旧浏览器不支持 Canvas/Geolocation API。

**缓解策略**:

1. 特性检测（`if (typeof HTMLCanvasElement !== 'undefined')`）
2. 优雅降级：不支持时显示静态背景图
3. Polyfill（仅在需要时加载）
4. 浏览器版本警告（建议升级）

### 风险 5: 主题适配问题 (Low)

**描述**: 背景动画可能与明暗主题冲突（可读性问题）。

**缓解策略**:

1. 背景不透明度可调（0.3-0.7）
2. 明暗主题使用不同色调（亮主题用浅色，暗主题用深色）
3. 前景内容添加半透明遮罩（确保可读性）
4. 用户可自定义背景透明度（设置面板）

## 备选方案 (Alternatives Considered)

### 备选方案 1: 使用视频背景

**描述**: 预渲染不同天气的视频文件，根据天气切换播放。

**优点**:

- ✅ 性能稳定（视频解码由浏览器优化）
- ✅ 视觉效果可控（专业设计师制作）
- ✅ 无需复杂动画代码

**缺点**:

- ❌ 文件体积大（每个天气 5-10MB，共 50-60MB）
- ❌ 缺乏灵活性（无法动态调整）
- ❌ 移动端流量消耗高
- ❌ 加载时间长

**为何未采纳**: 文件体积与移动端流量是主要阻碍。

### 备选方案 2: 使用第三方动画库 (Lottie)

**描述**: 使用 Lottie 播放设计师制作的 JSON 动画。

**优点**:

- ✅ 设计师友好（After Effects 导出）
- ✅ 文件小（矢量动画）
- ✅ 跨平台一致性

**缺点**:

- ❌ 需依赖设计师资源
- ❌ 动态性差（难以根据天气实时调整参数）
- ❌ 复杂交互支持有限

**为何未采纳**: 缺乏设计师资源，且动态性不足。

### 备选方案 3: 静态图片 + CSS 动画

**描述**: 使用静态海滩图片，通过 CSS `animation` 添加简单效果。

**优点**:

- ✅ 实现简单
- ✅ 性能最优
- ✅ 兼容性好

**缺点**:

- ❌ 视觉效果有限（无法实现复杂粒子系统）
- ❌ 缺乏真实感
- ❌ 天气联动效果弱

**为何未采纳**: 无法满足"动态动画"需求。

   - 方案：使用环境变量 + Vite 构建时注入（`.env` 文件，不提交到 Git）。
   - 待确认：是否需要代理服务器隐藏 API Key？

2. **默认城市**:
   - 问题：用户首次访问且拒绝定位时，显示哪个城市的天气？
   - 方案 A：使用 IP 定位（第三方服务如 ipapi.co）
   - 方案 B：默认北京/上海等大城市
   - 待确认：用户偏好？

3. **动画质量自动检测**:
   - 问题：如何判断设备性能以自动选择动画质量？
   - 方案 A：检测 GPU 型号（`WebGL` extensions）
   - 方案 B：运行性能基准测试（FPS 测试）
   - 方案 C：基于设备类型（移动端=低，桌面=高）
   - 待确认：哪种方案最可靠？

4. **夜间模式**:
   - 问题：晚上访问博客时，是否应该显示夜间海滩场景（月亮、星空）？
   - 方案 A：根据本地时间自动切换
   - 方案 B：始终显示白天场景
   - 待确认：是否属于 MVP 范围？（当前倾向于 Out of Scope）

5. **多语言适配**:
   - 问题：天气描述文字（如"多云"、"小雨"）需要多语言支持吗？
   - 方案 A：使用 i18next 添加天气相关翻译
   - 方案 B：不显示文字，仅视觉动画
   - 待确认：是否需要显示文字描述？
