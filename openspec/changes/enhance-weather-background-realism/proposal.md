## 动机 (Motivation)

当前天气背景系统已实现基本功能，但存在以下用户体验问题：

1. **视觉刺激过强**: 背景颜色过于鲜艳，天空渐变色彩饱和度高，长时间观看容易视觉疲劳
2. **布局不自然**: 当前设计是沙滩在底部、海洋在中间，不符合真实海滩视角
3. **背景占比过大**: 背景高度占满整个视口，干扰内容阅读
4. **缺乏动态时间感**: 太阳位置固定，无法体现一天中的时间变化
5. **场景元素单调**: 沙滩只有纯色，缺少植被点缀；海洋只有波浪，缺少生物元素

### 用户反馈

- "现在的天气背景很扎眼" - 需要降低颜色饱和度和亮度
- "背景很不真实" - 需要改进布局和增加自然元素
- "中间的大部分区域不要用颜色" - 需要减少背景对内容区的视觉干扰

### 目标

1. 创建更柔和、低调的视觉效果，支持内容阅读而非干扰
2. 采用更符合真实海滩场景的布局（左侧海洋、右侧沙滩）
3. 控制背景高度，为内容区留出更多干净空间
4. 增加动态时间模拟，提升场景的真实感和趣味性
5. 丰富场景元素（植被、鱼类），增强自然氛围

## 约束与假设 (Constraints & Assumptions)

### 技术约束

1. **Canvas 渲染性能**:
   - 新增元素（植被、鱼类、太阳轨迹）不能显著增加 CPU/GPU 负载
   - 需维持 60fps（桌面）/ 30fps（移动端）的流畅度
   - 低端设备通过 `quality` 参数降级渲染（减少元素数量）

2. **现有架构兼容**:
   - 基于当前 `BeachScene.tsx` 组件进行改进，避免重写
   - 保持 `sceneConfigs.ts` 配置结构，扩展新的配置项
   - 不破坏现有的天气状态切换逻辑

3. **浏览器兼容性**:
   - Canvas 2D API 基础功能（路径、渐变、变换）
   - 不依赖实验性 API

### 业务约束

1. **内容优先原则**:
   - 背景必须从属于内容，不能喧宾夺主
   - 中间区域（内容区上方）保持简洁，避免复杂图案干扰
   - 颜色对比度需确保文字可读性（WCAG AA 标准）

2. **主题系统集成**:
   - 需与现有的天气模式/主题模式切换兼容
   - 在天气模式下，背景需与透明组件协同工作
   - 夜间模式下需调整颜色方案（更暗的天空、月亮代替太阳）

3. **用户控制**:
   - 保持现有的背景模式开关功能
   - 考虑添加"减少动画"选项（响应 `prefers-reduced-motion`）

### 假设

1. 用户期望的"真实感"是柔和的艺术化表现，而非照片级写实
2. 横向布局（左海右滩）比垂直布局（上海下滩）更符合用户直觉
3. 太阳轨迹动画可采用简化的线性移动，无需精确的天文计算
4. 植被和鱼类可用简化的几何图形表示，不需复杂的 sprite 图像

## 提议的解决方案 (Proposed Solution)

### 高层设计

改进 `BeachScene.tsx` 组件的渲染逻辑，重新设计场景布局和元素：

#### 核心变更

1. **布局重构**:
   - 左侧 30-40% 区域为海洋（垂直渐变，深蓝到浅蓝）
   - 右侧 60-70% 区域为沙滩（米黄色，底部有过渡）
   - 高度控制在视口的 25-35%（底部固定或顶部固定）

2. **太阳动态系统**:
   - 根据本地时间计算太阳位置（简化算法：线性映射 0-24h 到 0-100% 水平位置）
   - 早晨：左侧低位 → 中午：中央高位 → 傍晚：右侧低位
   - 垂直位置用二次曲线模拟弧线轨迹
   - 夜间（18:00-6:00）显示月亮替代太阳

3. **颜色柔和化**:
   - 降低天空渐变的饱和度（从鲜艳蓝色 → 柔和灰蓝）
   - 减少光晕强度（太阳/月亮周围的发光效果）
   - 中间区域使用低饱和度或半透明色块（避免干扰内容）

4. **场景元素增强**:
   - **沙滩植被**:
     - 椰子树 2-3 棵（简化的树干 + 叶片）
     - 灌木/草丛 3-5 簇（随机位置）
   - **海洋生物**:
     - 小鱼 5-10 条（椭圆形，游动动画）
     - 气泡效果（可选，装饰性）

#### 架构影响

```typescript
// 伪代码
function calculateSunPosition(currentHour: number): SunPosition {
  const isNight = currentHour < 6 || currentHour >= 18;

  // 水平位置: 6am(0%) -> 12pm(50%) -> 6pm(100%)
  const normalizedHour = ((currentHour + 18) % 24) / 24; // 6am 对齐到 0
  const x = canvas.width * normalizedHour;

  // 垂直位置: 抛物线 (最高点在正午)
  const noonOffset = Math.abs(currentHour - 12) / 6; // 0-2
  const y = canvas.height * 0.1 + noonOffset * canvas.height * 0.15;

  return {
    x,
    y,
    size: isNight ? 30 : 40, // 月亮稍小
    isNightMode: isNight,
  };
}
```

function drawPalmTree(ctx, x, y, height) {
  // 树干 (褐色矩形)
  ctx.fillStyle = "#8B7355";

}

#### 4. 鱼类游动

```typescript
// 鱼对象
interface Fish {
  x: number;
  y: number;
  speed: number;
  direction: 1 | -1; // 左游或右游
  size: number;
}

function updateFish(fish: Fish[], oceanBounds) {
  fish.forEach((f) => {
    f.x += f.speed * f.direction;

    // 边界检测 - 转向
    if (f.x < oceanBounds.left || f.x > oceanBounds.right) {
      f.direction *= -1;
    }

    // 轻微上下摆动
    f.y += Math.sin(Date.now() * 0.001 + f.x) * 0.5;
  });
}

function drawFish(ctx, fish: Fish) {
  ctx.fillStyle = "rgba(255, 165, 0, 0.6)"; // 半透明橙色
  ctx.beginPath();
  ctx.ellipse(fish.x, fish.y, fish.size, fish.size * 0.6, 0, 0, Math.PI * 2);
  ctx.fill();

  // 尾巴 (简化三角形)
  ctx.fillStyle = "rgba(255, 140, 0, 0.5)";
  ctx.beginPath();
  const tailX = fish.x - fish.direction * fish.size;
  ctx.moveTo(fish.x, fish.y);
  ctx.lineTo(tailX, fish.y - fish.size * 0.5);
  ctx.lineTo(tailX, fish.y + fish.size * 0.5);
  ctx.fill();
}
```

## 替代方案 (Alternatives Considered)

### 方案 A: 完全重写为 SVG 动画

**优点**:

- DOM 操作更易调试
- CSS 动画性能更好（硬件加速）
- 响应式布局更简单

**缺点**:

- 粒子系统（雨、雪）难以实现
- 复杂渐变和滤镜效果浏览器兼容性问题
- 已有 Canvas 代码需全部弃用（高风险）

**决策**: ❌ 不采用 - Canvas 更适合动态粒子效果，重写成本过高

### 方案 B: 使用预渲染视频背景

**优点**:

- 视觉效果可达到影视级别
- 开发成本低（导出视频即可）

**缺点**:

- 文件体积大（压缩后仍需 5-10MB）
- 无法动态响应天气数据
- 移动端流量消耗高

**决策**: ❌ 不采用 - 违背"动态天气联动"的核心价值

### 方案 C: 保持垂直布局，仅调整颜色

**优点**:

- 改动最小，风险低
- 现有代码几乎不变

**缺点**:

- 无法解决"不真实"的核心问题
- 用户明确要求横向布局

**决策**: ❌ 不采用 - 未能解决主要痛点

## 影响分析 (Impact Analysis)

### 用户影响

- ✅ **正面**: 视觉舒适度提升，内容可读性增强
- ✅ **正面**: 场景更真实，增加沉浸感
- ⚠️ **中性**: 习惯当前布局的用户需适应新设计（预期影响小）
- ⚠️ **风险**: 太阳动态可能在某些时段位置不理想（需测试调优）

### 性能影响

- 新增元素渲染成本:
  - 植被 3-5 个静态对象: +5% CPU
  - 鱼类 5-10 个动画对象: +10% CPU
  - 太阳轨迹计算: +1% CPU（每帧一次）
- **总计**: 预计 15-20% 性能开销
- **缓解措施**:
  - `quality="low"` 模式下减少鱼类数量（2-3 条）
  - 移动端禁用植被阴影效果
  - 太阳位置每秒更新一次（而非每帧）

### 开发影响

- 修改文件:
  - `BeachScene.tsx` - 主要改动
  - `sceneConfigs.ts` - 扩展配置
  - `types.ts` - 新增接口
  - `style.scss` - 布局调整
- 新增文件: 无
- 测试范围:
  - 6 种天气状态的渲染验证
  - 24 小时太阳轨迹测试
  - 低端设备性能测试

### 依赖影响
